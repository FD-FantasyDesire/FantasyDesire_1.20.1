# 星海领域 · 地面覆盖原型

基于 [`Starfield`](../Starfield/README.md) 的地形覆盖星海，参考 `FrostStormFieldRenderer` / `fd_frost_field.fsh` 的双深度投影覆盖方式。保留蓝紫银河、暗尘埃与三层恒星，移除领域球壳；边缘呈持续流动的不规则轮廓，流星默认每个方向星区 **1.1 颗/秒**，原星空为每 17 秒一颗。

这是 `shaderDev` 独立原型，不注册 Minecraft shader，也不改变寒霜风暴的游戏效果。

## 运行

在项目根目录执行（Node.js 18+，无需 npm 依赖）：

```powershell
node shaderDev/StarSea/serve.cjs
```

打开 <http://127.0.0.1:8768/preview.html>，按 `Ctrl+C` 停止服务。可加端口参数，例如 `node shaderDev/StarSea/serve.cjs 8769`。服务仅绑定本机回环地址。

需要 **WebGL 2**。本作品使用场景深度纹理、自定义 uniform、片元导数与多 pass，因此使用独立宿主；不能直接把 `main.fsh` 放进 WebGL 1 GLSL Canvas。

浏览器读取桌面 GLSL 150 的 `main.vsh` / `main.fsh`，由宿主转换为 GLSL ES 3.00，再展开 `// @include STARFIELD_SHARED` 标记。`sky.glsl` 另提供连续方向空间的星云、恒星与流星，由 `// @include STARSEA_SKY` 展开。共享段来自 `../Starfield/main.frag` 中 `STARFIELD_SHARED_BEGIN` / `STARFIELD_SHARED_END` 之间的常量和函数；原星空仍可独立在 GLSL Canvas 使用。这里的标记由 `preview.js` 处理，不是 GLSL 原生 include。

## 预览操作

- 拖动画面环绕，滚轮缩放；也可以使用角度滑条与俯视、低角度、默认视角按钮。
- 暂停、时间轴、逐帧用于检查边缘流动和流星出生/消失；逐帧为 `1/60` 秒。
- “重新展开”从时间 0 开始，领域在 1.8 秒内从中心展开不规则轮廓。
- 半径 `2–7` 格；边缘起伏 `0–40%`，默认 `26%`；流星每个星区 `0–2` 颗/秒；地面覆盖 `0–100%`。
- “覆盖范围”显示实际地形覆盖遮罩；“被实体遮挡的区域”用橙红色标识原本会被覆盖、但在正常模式中被深度排除的像素。
- 人物/遮挡物、台阶、L 形墙可分别隐藏，便于核对遮挡和地形贴合。
- 渲染精度限制长边尺寸，同时受页面尺寸与设备像素比约束。
- “重新加载着色器”读取当前源码；编译失败保留上一版程序并显示错误。
- “保存 PNG”只保存实际画布。

可通过查询参数固定审查状态，如 `preview.html?time=6&paused=1&pitch=84&yaw=0`。支持 `time`、`paused=1`、`radius`、`edge`、`rate`、`opacity`、`yaw`、`pitch` 和 `debug=0/1/2`；数值参数受界面范围限制。

## 渲染结构

1. **地形 pass**：将地板与台阶绘制到独立目标，保存颜色及 24 位地形深度 `BlockDepthSampler`。
2. **完整场景 pass**：复制地形颜色/深度到第二个目标，再绘制人物和遮挡物，得到完整场景深度 `DepthSampler`。
3. **合成 pass**：把完整场景颜色复制到最终目标，以全屏三角形读取两份独立深度，重建相机相对坐标。对范围内所有可见地形面绘制星海，使用预乘 Alpha 合成。

采样目标与写入目标始终分离。星海不依靠贴地四边形，不绘制任何球面几何，不使用球面求交；地面、台阶、竖直墙面及背面共同显示同一片方向空间星空。范围由三维流体距离场决定，没有朝向过滤或独立高度截断。

两份深度沿视线以 **格** 为单位比较，使用与 FrostField 一致的 `0.025` 格容差。人物只进入完整场景深度，因此其可见身体保持原材质。演示方块和人物由宿主生成，不是 Minecraft 场景采样，也没有验证游戏内水面、透明方块或其他模组的渲染阶段。

## 星空、岸线与流星

- 随机星云簇使用连续方向空间的程序化噪声；每个云团按 `NebulaSeed` 生成亮度、云丝和主色槽。移动领域或相机时会按此前的程序化方式重新生成局部景观，不绑定世界坐标。
- 星云调色板循环包含深蓝、天蓝、橙、青绿、深红、紫、黄七组色段；配色模式按云团随机分布，约 75% 单色、20% 混 2 色、5% 混 3 色，避免整片区域只有单一色相又保持纯色为主。
- 星空颜色和视觉层次沿用上一版；恒星、银河和随机星云都沿观察方向采样，由连续三维程序化噪声生成。地形只提供覆盖遮罩，像揭开星海窗口；星云不读取地形表面位置，因此不会把单个彩色样本糊在窗口表面。
- 恒星方向采样和星云簇都不使用经纬度 UV 或六面贴图，因此墙角不会出现接缝或违和拉伸。星云直接在单位视线中生成宏观云团、云丝和亮核，移动相机时按此前方式重新生成局部景观。
- 方向射线负责读取当前可见地形像素上的远景恒星和星云；它们不是可见球壳，也不会把地面范围变成球体。
- 边缘使用连续三维噪声扭曲，加上 3 / 5 / 7 阶闭合角向波。上下极点平滑消除角向项，墙面上也有流体范围起伏；起伏为 0 时采用规则距离范围，但仍不绘制外壳。
- 整个不规则范围独立生长，羽化与柔光跟随同一边界，不额外叠加硬裁切。
- 六个方向星区生成流星；星云簇沿用局部程序化生成，噪声相位随累计时间轻微变化，边缘起伏和流星也继续运动；流星轨迹跨地面和墙角连续，每星区最多 4 个候选、每次寿命 1.65 秒，频率是每星区值。
- 星空抗锯齿根据观察射线的像素角宽计算，与地面倾斜角无关；全部效果导数在 discard 与非一致分支前求值。
- 覆盖率默认 100%，范围内部取代原地面颜色，柔边逐渐露出地形。边缘光芒在片元中直接生成，没有后处理 Bloom。

## 正式管线映射

| 输入 | 原型中的来源 / 单位 | Minecraft 对应 |
| --- | --- | --- |
| `DepthSampler` | 完整场景离屏深度 | `AFTER_LEVEL` 的场景深度副本 |
| `BlockDepthSampler` | 地形离屏深度 | 参考 FrostField 在 `AFTER_CUTOUT_BLOCKS` 保存的深度 |
| `InvViewProj` | 投影 × 仅含旋转的视图矩阵的逆 | FrostField 同型逆矩阵 |
| `FieldCenter` | 领域中心减相机位置，格 | 实际领域中心的相机相对位置 |
| `FieldRadius` | 基准空间半径，格 | 与玩法范围分开定义视觉波动包围盒 |
| `FieldTime` | 累计秒 | Java 上传的秒数，不能直接沿用 FrostField 的 tick |
| `FieldAge` | 激活后的秒数 | 实例年龄加 partial tick 后除以 20 |
| `FieldOpacity` | 0–1 | 地面覆盖强度 |
| `EdgeMotion` | 0–0.4 | 半径起伏比例 |
| `MeteorRate` | 每星区每秒 0–2 颗 | 流星频率 |
| `NebulaClusterGain` | 0–2 | 随机星云簇强度 |
| `NebulaSeed` | 0–9999 | 随机星云簇种子 |
| `DepthUvScale` | 原型为 `(1,1)` | 主渲染目标 view 尺寸 / 实际纹理尺寸 |
| `DebugView` | 0 正常、1 覆盖、2 遮挡 | 正式场景固定为 0 或开发调试选项 |

迁移时展开共享源码并提供 shader JSON；顶点格式使用 `POSITION_TEX`。在 `FDShaderHandler` 注册、提供 getter 与加载检查，每帧重新取实例以兼容 `F3+T`。预乘混合因子为 `ONE / ONE_MINUS_SRC_ALPHA`，不写深度；本原型包含显示用曝光映射与近似 gamma 编码，正式合成需按目标色彩空间适配。

起伏范围可以超过基准半径，不能直接沿用半径为 `FieldRadius` 的球形视锥裁剪。按当前参数上限，三个坐标方向的包围范围至少取 `±1.7 × FieldRadius`，另加柔边余量。视觉起伏是否影响玩法判定需另外明确。

## 成本与验收

包含地形绘制、场景复制、实体绘制与全屏覆盖。两个离屏目标各有 RGBA8 颜色和深度纹理；分辨率和并发覆盖面积都会影响成本。范围外像素先做深度和边界检查再跳过星空噪声；范围内有方向银河、方向星云的 4 层三维 FBM、最多 81 个恒星候选和 24 个流星候选，并增加边缘三维噪声。

优先用精度选项降低分辨率；预览 FPS 包含浏览器调度，不能当作 GPU 单 pass 耗时或 Minecraft 帧率结论。此目录没有接入游戏，因此不以 Gradle 编译代替视觉验收。

已在内置浏览器 WebGL 2 中编译并检查默认斜视画面：地面、台阶与 L 形墙显示连续星图，人物与遮挡物保持独立材质。全部角度的数学采样不依赖地形 UV；透明场景、游戏内深度与资源重载仍需正式接入后验收。

## 局部程序化生成

星云簇恢复为相机附近的局部程序化景观，不固定于世界坐标。覆盖计算和星图采样仍不要求世界原点附近：

- `rayDirection` 来自逆视图投影矩阵的近远点差，只含视线方向；银河、恒星和流星在这个单位方向上求值，与世界坐标原点无关。
- `blockPosition` 和 `FieldCenter` 都是相对相机的 `vec3`，先相减得到领域局部坐标，用于边缘噪声和覆盖范围。不要把绝对 `BlockPos` 或双精度世界坐标直接转成 float 后再相减。
- `directionNebulaClusters` 只接收单位 `rayDirection`，用多层三维 FBM 生成局部云团、丝状结构和亮核；星云位置和颜色不绑定世界坐标，视线在地面、墙面和墙角之间连续。

银河并非所有方向同样明亮。`directionGalaxy` 用 `exp(-latitude² / 0.019)` 形成固定方向的银河带，朝向远离该带时，银河辐射会很弱；局部程序化星云簇仍会提供随机色块、星点和暗背景。若需要每个视角都有银河带，应增加第二条方向带或单独的全向云雾底层。

若整片星海覆盖都消失，则还应检查深度链路：地形离相机很远时，24 位深度精度、视锥 `far` 设置或深度 UV 尺寸不匹配可能让 `blockDepth >= 0.99999`，使覆盖被跳过。这是相机距离与渲染输入的问题，和整体场景离世界原点的距离不同。正式接入应使用匹配主目标的深度副本，保持逆视图投影矩阵与当前帧一致。调试时先切到“覆盖范围”：若看不到青绿色遮罩，先查范围、深度和矩阵；若遮罩存在而银河不亮，再查观察方向、曝光、星图强度或色彩空间。

Java 侧只需继续上传相机相对顶点和领域相对位置；局部星云函数不读取绝对 `BlockPos`，因此无需维护世界单元原点或把大坐标拆分后上传。
