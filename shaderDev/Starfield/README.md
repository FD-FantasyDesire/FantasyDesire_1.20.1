# 星海 · 程序化星空

自包含的 **WebGL 1 / GLSL ES 1.00** 星空原型。深蓝底色上叠加蓝紫银河、暗尘埃带、三层冷暖恒星、独立闪烁与偶发流星；所有形状由程序计算，无贴图或外部资源。

## GLSL Canvas

打开 [`main.frag`](main.frag)，运行 VSCode **GLSL Canvas**（`circledev.glsl-canvas`）的 **Show GLSL Canvas** 命令即可预览。保存后重新编译。鼠标调整观察位置；宿主尚未提供鼠标坐标时采用中性视角。

## 浏览器预览

在项目根目录运行（需要 Node.js 18 或更高版本，无需安装 npm 依赖）：

```powershell
node shaderDev/Starfield/serve.cjs
```

打开 <http://127.0.0.1:8767/preview.html>。服务只绑定本机；按 `Ctrl+C` 停止。端口被占用时可执行 `node shaderDev/Starfield/serve.cjs 8768`，然后访问对应端口。

也可直接打开 [`preview.html`](preview.html)，通过 **选择 main.frag** 按钮载入同目录的着色器。浏览器禁止 `file://` 页面自动读取邻近文件；本地选择器不会上传到服务器。此方式修改文件后请重新选择文件，以取得最新内容。

- **暂停 / 继续、前进一帧、时间轴**：逐帧步长为 `1/60` 秒；拖动时间轴自动暂停。动画使用累计秒数，不在时间轴终点重置。
- **拖动或视角滑条**：平移观察窗口；双击画面或点击“视角归中”恢复默认位置。
- **画质**：限制实际渲染长边为 960 / 1440 / 1920 像素；同时受页面尺寸和设备像素比限制，状态栏显示实际尺寸。
- **重新加载**：通过本地服务读取刚保存的 `main.frag`；编译失败会显示错误并保留上一版效果。
- **保存画面**：保存当前画布的 PNG，不包含预览界面。

浏览器与 GLSL Canvas 读取同一个 `main.frag`，宿主没有复制效果实现。页面未使用额外 uniform、GLSL 扩展、纹理或 CDN。

## 输入和坐标

| 输入 | 单位与约定 |
| --- | --- |
| `u_time` | 非负累计秒数；负值按 0 处理 |
| `u_resolution` | 实际渲染目标像素尺寸；各分量保底为 1 |
| `u_mouse` | 左下角为原点的像素坐标；`(0,0)` 为中性输入，其余输入限制到画布范围 |

画布中心为原点，以短边归一化；短边覆盖 `[-1,1]`，宽屏不会拉伸星核。视角最大移动量为横向 `±0.55`、纵向 `±0.35` 个归一化坐标单位。

星图是可平移的二维连续背景，没有天空球、三维相机或经纬度接缝处理。所有星层与银河使用同一个坐标变换，避免镜头移动时不同距离的恒星出现夸张视差。

## 可调参数

在 `main.frag` 顶部修改常量并保存：

| 参数 | 默认 | 含义 / 建议范围 |
| --- | --- | --- |
| `SEED` | 27 | 星图与云团种子，建议 `0–9999` 的整数 |
| `STAR_DENSITY` | 1.0 | 恒星出现概率倍率，建议 `0–2`；0 关闭星层 |
| `NEBULA_GAIN` | 1.0 | 银河强度，建议 `0–2`；0 同时关闭星云辐射和尘埃遮挡 |
| `TWINKLE` | 0.20 | 闪烁幅度，限制到 `0–1`；0 为恒定亮度 |
| `DRIFT` | 0.035 | 缓慢镜头漂移振幅；0 为固定镜头 |
| `METEOR_GAIN` | 0.65 | 流星亮度；0 关闭 |
| `EXPOSURE` | 1.15 | 预览曝光，建议 `0.5–2` |
| `CLOUD_OCTAVES` | 5 | 每次 FBM 的编译期层数，建议 `3–5` |

仅有 `u_time` 参与动画：星点位置和云团噪声不随时间重新随机生成。每颗星使用固定相位与频率平滑闪烁，镜头按 180 秒的闭合轨迹缓慢漂移，位置与速度在轨迹交界处连续；整个场景并不按 180 秒循环。

## 形状与生命周期

- `galaxy`：倾斜坐标下的五层 FBM、域扭曲、细纹与暗带；输出银河辐射及远处恒星的透过率。前景亮星不被远处尘埃遮挡。
- `stars`：每层每格最多一颗随机偏移的恒星，三层分别使用不同网格尺度、占用概率和亮度。扫描相邻 `3×3` 格，星核、光晕和十字光芒在半径 0.30–0.46 格间平滑归零，避免露出网格边界。
- 星核按实际像素宽度做高斯展宽并补偿能量；无需片元导数。远处小星光晕较弱，仅少量前景亮星带十字光芒。
- `meteor`：每 17 秒的第 2.0–3.4 秒出现一次有限尾迹。出生前和消失后返回零；尾迹有显式尾端与头端，换周期时已经完全淡出。检查点可选 1.99 / 2.06 / 2.65 / 3.39 / 3.41 / 16.99 / 17.01 秒。
- 输出 alpha 恒为 1，适合作为背景预览。末尾进行指数曝光映射和近似 sRGB 编码；星芒由片元函数直接绘制，没有后处理 Bloom。

## 成本与验证边界

单个全屏 pass；每片元最多检查 27 个恒星候选，并执行 4 次 FBM（默认每次 5 层，每层 4 次角点 hash）。主要成本是覆盖面积、程序化噪声和恒星核计算。优先降低宿主渲染分辨率，其次降低 `CLOUD_OCTAVES`；减少恒星密度仍保留候选网格的 hash 计算。将 `NEBULA_GAIN` 设为 0 主要用于视觉切换，不代表自动省去全部云团运算。

已在 Codex 内置浏览器的 WebGL 1 上下文中成功编译并检查默认宽屏画面；GLSL Canvas 扩展及 Minecraft 内表现需在对应宿主继续验收。预览页帧率是实际页面绘制频率，包含浏览器调度开销，不是 GPU 计时结果，也不代表 Minecraft 并发场景性能。

`highp` 不可用时回退 `mediump`，但 hash、细小恒星和长时间动画可能损失精度；低精度设备不保证相同星图。长期连续运行时，可由正式宿主上传单独的动画相位，避免一个越来越大的秒数同时承担全部计算。

## 迁移到 Minecraft

本目录不会自动载入游戏。正式迁移时按 [`shaderDev` 总规范](../README.md) 处理：

1. 使用桌面 `#version 150`，去掉 ES 精度声明，并把 `gl_FragColor` 改为明确的片元输出。
2. 根据用途选择模型 UV、天空方向或屏幕空间。若需要真正的环绕天空，先改为方向空间分布并验证全向连续性，不能把当前二维窗口直接当成无缝天空球。
3. 将 `u_time` 映射到 Java 上传的秒数，说明时间来源；原版 `GameTime × 24000 / 20` 才是日周期内的秒数，周期回绕不适合直接驱动此处累计流星事件。
4. 为真实分辨率与观察位置提供输入，移除鼠标预览逻辑。若作附着材质，另行定义透明度；当前不透明背景不能直接使用加法混合。
5. 按目标色彩空间决定是否移除末尾曝光与 gamma 编码。正式 HDR/Bloom 需要合适的渲染目标与合成流程。
6. 配套 shader JSON、匹配 attributes 的 `DefaultVertexFormat`、`FDShaderHandler` 注册/getter/加载检查，每帧重新取实例以适配 `F3+T`，再检查深度状态与实际场景成本。
